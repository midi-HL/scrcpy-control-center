# Scrcpy Control Center 中文使用说明

> 本文基于 `master` 分支的源码（`d4c9c96`）整理，说明这个仓库**实际做了什么、怎么跑起来、各模块如何协作，以及哪些地方目前有坑**。它不是功能承诺清单；未实装或代码里存在偏差的地方都会在「已知问题」里写明。

## 1. 一句话定位

Scrcpy Control Center 是 Windows 上的一个 **scrcpy 图形化启动器 / 进程管理器**，用 C++17 + Dear ImGui + DirectX 9 写成，目标平台是 **Windows 8.1 32 位（x86）**。它不实现投屏协议，也不重新实现 scrcpy：它把界面里的选项拼成 `scrcpy` 命令行参数，启动并监控 `scrcpy.exe`，再通过 `adb.exe` 做设备发现、应用管理和虚拟显示相关操作。

核心思路是**参数数据驱动**：`config/scrcpy_features.json` 定义每个 scrcpy 参数对应的控件类型、默认值、取值范围和依赖关系；UI、命令生成、参数禁用逻辑都从这份 JSON 读取，新增一个普通参数通常只需改 JSON。

## 2. 运行环境与构建

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 8.1 或更高版本；工程强制 `Win32 / x86`，并定义 `WINVER=0x0603` 等宏限制到 Win8.1 API |
| 编译器 | Visual Studio 2019 / 2022，C++ 桌面开发工作负载；也保留 MinGW 的 CMake 分支 |
| 运行时依赖 | `scrcpy.exe` 与 `adb.exe`，可放在 PATH，或放到程序目录，或在「设置」页指定路径 |
| 建议 scrcpy 版本 | 配置声明 `target_scrcpy: "2.4"`，README 写 v2.4+ |
| 图形 | DirectX 9；界面会尝试加载微软雅黑/黑体/宋体等 CJK 字体，找不到时退回 ImGui 默认字体 |

构建：

```bat
git clone https://github.com/midi-HL/scrcpy-control-center.git
cd scrcpy-control-center
build.bat
```

等价的 CMake 命令：

```bat
cmake -S . -B build -A Win32
cmake --build build --config Release
```

`build.bat` 与 CMake 的 POST_BUILD 都会把 `config/` 复制到输出目录。程序默认按**当前工作目录**读取 `config/scrcpy_features.json`、`config/settings.json`，因此建议从包含 `config/` 的目录启动 `ScrcpyControlCenter.exe`。CI 见 `.github/workflows/build.yml`：`master`/`main` 的 push、PR 和 `v*` tag 会构建 Win32 Release，tag 会生成 Release 附件。

## 4. 启动到投屏的数据流

1. `App::init()` 加载 `scrcpy_features.json`，用其中的默认值初始化 `StateManager`，再读 `settings.json`、恢复 `config/last_state.json`。
2. 初始化 Win32 窗口与 DX9 设备、ImGui（尝试加载中文字形）、图标缓存目录，随后启动设备轮询线程。
3. `ContentPanel` 按所选菜单调用 `renderFeatureControls(category)`，从 JSON 生成滑块、复选框、下拉框、输入框；`FeatureParser::isFeatureDisabled()` 根据 `disabled_by` 禁用互相冲突的选项。
4. 底部命令预览调用 `CommandBuilder::buildArgs(serial)`：先为多设备场景加入 `-s <serial>`，再按 JSON 顺序把非默认值拼成参数。
5. 点击「启动 scrcpy」后，`ProcessManager::startScrcpy()` 通过 `cmd.exe /c "chcp 65001 >nul && ..."` 创建隐藏子进程，用匿名管道读取 stdout/stderr 并写日志；运行中的实例显示在表格里，可单独停止或全部停止。
6. 退出时保存 `config/last_state.json`，停止轮询，并终止已登记的 scrcpy 子进程，避免残留后台进程。

## 5. 界面功能

侧栏共 14 项：设备、连接、显示、音频、控制、录制、虚拟显示、应用管理、摄像头、游戏、高级、日志、设置；另有底部命令预览区。

- **设备**：表格显示序列号、型号（`getprop ro.product.model`）、状态、USB/WiFi 类型；可手动刷新、选择设备。轮询间隔默认 20 秒，设置页可调 5–60 秒。
- **连接**：`adb connect IP:5555` 连接无线设备；对已选设备执行 `adb tcpip 5555`。
- **显示 / 音频 / 控制 / 录制 / 摄像头 / 虚拟显示 / 高级**：按 JSON 分类动态生成参数控件。OTG 开启时，显示与音频页会给出警告，相关控件通过依赖规则禁用。
- **虚拟显示**：可填写 `WIDTHxHEIGHT`（或带 `/DPI`）并逐行填入多个包名，批量以 `--new-display=... --start-app=... --flex-display --no-vd-system-decorations` 启动多个 scrcpy 实例。
- **应用管理**：用 `pm list packages -e/-d` 汇总已启用与已停用应用，支持按包名过滤；冻结用 `pm disable-user --user 0`，解冻用 `pm enable`，也可用 `pm uninstall [-k]` 卸载、`monkey` 启动、在虚拟显示中启动。图标功能通过 `pm path` 拉取 APK、直接解析 ZIP 中的 `ic_launcher`/`mipmap` PNG 并缓存到 `cache/icons/`。
- **游戏**：主要是 OTG 与高级参数入口，并提示 WinUSB 驱动（Zadig）相关事项。
- **高级**：粘贴一条 scrcpy 命令，`CommandBuilder::parseCommandString()` 按 token 反查 JSON 参数，回填界面状态；界面底部同时显示即将执行的命令预览。
- **设置**：中/英文切换、明暗主题、加载三套预设、保存自定义预设、设置 scrcpy/adb 路径、轮询间隔、是否抓取图标、控制台编码（Auto / UTF-8 / GBK / Big5 / Shift-JIS / EUC-KR / Latin-1），点击保存写回 `settings.json`。
- **日志**：展示 scrcpy/adb 输出与程序内部日志，便于排查启动失败。

## 6. 配置文件

`config/scrcpy_features.json` 顶层为 `version`、`target_scrcpy`、`features` 数组。一个条目大致是：

```json
{
  "id": "max_fps",
  "gui_label_en": "Max FPS",
  "gui_label_zh": "最大帧率",
  "category": "display",
  "parameter": "--max-fps",
  "type": "int",
  "default": "0",
  "min": 0,
  "max": 240,
  "disables": [],
  "disabled_by": ["otg"]
}
```

支持的类型：`int`（`min`/`max` 决定滑块）、`boolean` / `boolean_inverse`、`enum`（`options` 数组）、`string`。`disabled_by` 表示当某个依赖项为 true / 非零 / 非默认字符串时禁用此项。当前 JSON 有 **56 个条目、55 个唯一 id、7 个分类**（`no_playback` 重复出现一次）；README 里写的「46 参数」与当前配置不一致。

三套预设的用途：

| 预设 | 关键取向 |
| --- | --- |
| `gaming.json` | 120 FPS、16M 视频码率、H.264、低缓冲 |
| `streaming.json` | 60 FPS、24M、H.265、1920 限制、窗口置顶 |
| `battery_saver.json` | 15 FPS、2M、720 限制、关音频、关闭屏幕 |

`settings.json` 的字段：`language`、`theme`、`scrcpy_path`、`adb_path`、`fetch_app_icons`（默认 true）、`device_polling_interval`（默认 20 秒）。若路径仍是默认值，程序启动时会自动改成 exe 同目录下的 `scrcpy.exe` / `adb.exe`。

## 7. 已知问题与使用提醒

这些是从当前源码能直接看出的限制，不是猜的：

- **README 数字过时**：README 写「46-Parameter」，实际 JSON 是 56 条目 / 55 个唯一 id。
- **控件标签与翻译表对不上**：`renderFeatureControls()` 用 `TR(feature.gui_label_en)` 取标签，但 i18n 表里主要存的是 `menu_*`、`desc_*`、`feat_*` 这类键，没有 `"Max Size"` 等键；多数参数会显示 JSON 里的英文标签。参数说明提示框用 `feat_<id>` 键，这部分能命中。
- **中文词条质量**：抽查的中文词条本身是正常 UTF-8；但个别条目（如 `feat_gamepad`、`feat_new_display`）在源码里显示为乱码文本，切到中文界面时可能显示异常。
- **部分功能只是参数入口**：「游戏」页实际渲染的是 `advanced` 分类并在文案里提到手柄/OTG；`gamepad`、`no_control` 等词条存在于 i18n 表，但不在当前 `scrcpy_features.json` 的 56 个条目中，因此没有对应控件。
- **主启动按钮不注入序列号**：`renderCommandPreview()` 的预览会带 `-s <serial>`，但点击启动时调用 `startScrcpy(cfg.scrcpyPath, args, "", {})`；`args` 已由 `buildArgs(serial)` 生成，所以通常仍能指向所选设备。虚拟显示批量启动则显式使用 `--new-display` 等参数并传选中 serial 作为元信息。
- **命令拼接较朴素**：`createProcessWithPipe()` 直接把参数拼进 `cmd.exe /c` 字符串，没有逐参数加引号；含空格的路径或参数有出错风险。启用 UTF-8 代码页（`chcp 65001`）后，`Encoding` 模块仍可在日志里按所选代码页转换文本。
- **进程终止是强杀**：`stopScrcpy()` / `stopAll()` 使用 `TerminateProcess`，不是向 scrcpy 发关闭信号；录制中的文件可能来不及正常收尾。
- **配置目录依赖工作目录**：`App::init()` 使用相对路径 `config/...`。从别的目录启动快捷方式时，可能读不到 `scrcpy_features.json`，界面会缺少参数并在日志里报错。
- **应用管理会改动设备状态**：冻结、解冻、卸载都是真实 adb 操作，且代码按 `com.android.` / `android.` / `com.google.` 前缀判断系统应用；对系统包执行前请自行确认。
- **图标提取会拉取 APK**：开启 `fetch_app_icons` 时会把设备上的 APK 临时拉到本机，再解析 ZIP 取 PNG；大包或大量应用会产生额外 I/O。
